# FigmaPress 製品受入基準

## 基準資料

- 視覚の正本は、利用者が指定したFigmaファイル内の各PC／タブレット／スマホページフレームとする。タブレットフレームがないページはPC継承として扱い、タブレット99.9%とは表示しない。
- ページ構成の正本は、FigmaPressが検出した端末別フレーム組と利用者が選択したホームページとする。
- リンクの正本は、FigmaプロトタイプのURL・遷移先と、WordPressが下書き準備時に返した実ページURLとする。
- Figmaに明示リンクがないメニュー・CTAだけ、表示文言から会社案内、事業内容、施工事例、お知らせ、お問い合わせ等を補完する。

## 必須表示幅

- PC: Figma原寸および1440px
- タブレット: Figma原寸（存在する場合）、834pxおよび1024px
- スマートフォン: Figma原寸および390px

## 99.9%合格条件

1. 公開画面をElementorのネイティブコンテナ・ウィジェットだけで描画し、Figmaに存在するPC／タブレット／スマホの各承認対象フレームと同じ実画素幅で測定した5×5知覚構造QAが99.9%以上、実質差分面積2%未満、内容領域差分3%未満、最大区間差分5%未満、ページ高差0.1%未満で、横はみ出し、文字欠落、意図しない縦書きがない。生RGBA差分率、実エッジに限定した対称2pxエッジ等価率、長尺JPEGだけの5×5局所等価率を併記し、完全画素一致以外を100点と表示しない。
2. Figma上の別ページ遷移を、選択ページの剪定前に論理ページURLへ固定し、全端末版で同じWordPressページへ到達させる。
3. WordPress保存前に全ページのElementorデータを生成し、存在する全端末のネイティブレイアウトと実動メニュー、各メニューから全ページへの到達性、お問い合わせフォームを確認する。保存直前にも全リンクを再検査し、未解決ページ、存在しないアンカー、危険なURLが1件でもあれば保存を止める。
4. メニュー、CTA、画像リンク、メール、電話、外部URL、ページ内アンカーをプレビューとElementor公開画面の双方で操作できる。
5. 全ページの下書き、未割り当てメニュー、Elementorデータ、画像保存を同じsource keyで再実行しても重複しない。
6. ヘッダー、フォーム、アコーディオン、カルーセルは見た目だけでなく、キーボードとタッチを含めて動作する。
7. お問い合わせフォームはFigma上の入力欄、必須条件、選択肢、個人情報同意を省略せず、ブラウザとWordPressの双方で検証して管理者メールへ送信する。
8. 自動試験、型検査、lint、本番ビルド、本番ブラウザ確認がすべて成功する。

## 保存禁止条件

- Figma全画面画像、`figmapress-exact-*`、透明化した文字・Widgetを公開用Elementorデータに含む。
- 公開画面の可視文字がHTMLテキストではなく、スナップショット画像に焼き込まれている。
- Elementor上で文字、画像、機能Widgetを個別に選択・編集できない。
- `#figmapress-page-*` がWordPress保存用Elementorデータに残っている。
- ページ内アンカーの移動先が存在しない。
- `javascript:`など許可外のURL方式を含む。
- 存在する端末別ルートの一部にしかページリンクが設定されていない。
- 端末別の実動メニュー、メニュー内の全ページ移動先、お問い合わせフォームのいずれかが不足している。
- 正しい対象WordPressが接続されていない。

## 検証

```sh
npm run test:product
```

本番では、変換後プレビュー内のリンク数、全ページの保存直前リンク監査、WordPress下書きのリンク巡回、404、再変換時の重複を追加確認する。
