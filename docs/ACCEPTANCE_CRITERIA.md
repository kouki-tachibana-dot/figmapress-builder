# FigmaPress 製品受入基準

## 基準資料

- 視覚の正本は、利用者が指定したFigmaファイル内の各PC/SPページフレームとする。
- ページ構成の正本は、FigmaPressが検出したPC/SPペアと利用者が選択したホームページとする。
- リンクの正本は、FigmaプロトタイプのURL・遷移先と、WordPressが下書き準備時に返した実ページURLとする。
- Figmaに明示リンクがないメニュー・CTAだけ、表示文言から会社案内、事業内容、施工事例、お知らせ、お問い合わせ等を補完する。

## 必須表示幅

- PC: Figma原寸および1440px
- タブレット: 1024px
- スマートフォン: Figma原寸および390px

## 99.9%合格条件

1. PC/SPとも承認対象フレームとの視覚QAが99.9%以上で、ページ高差、横はみ出し、文字欠落、意図しない縦書きがない。
2. Figma上の別ページ遷移を、選択ページの剪定前に論理ページURLへ固定し、PC/SPで同じWordPressページへ到達させる。
3. WordPress保存直前に全リンクを再検査し、未解決ページ、存在しないアンカー、危険なURLが1件でもあれば保存を止める。
4. メニュー、CTA、画像リンク、メール、電話、外部URL、ページ内アンカーをプレビューとElementor公開画面の双方で操作できる。
5. 全ページの下書き、未割り当てメニュー、Elementorデータ、画像保存を同じsource keyで再実行しても重複しない。
6. ヘッダー、フォーム、アコーディオン、カルーセルは見た目だけでなく、キーボードとタッチを含めて動作する。
7. 自動試験、型検査、lint、本番ビルド、本番ブラウザ確認がすべて成功する。

## 保存禁止条件

- `#figmapress-page-*` がWordPress保存用Elementorデータに残っている。
- ページ内アンカーの移動先が存在しない。
- `javascript:`など許可外のURL方式を含む。
- PC/SPのどちらか一方にしかページリンクが設定されていない。
- 正しい対象WordPressが接続されていない。

## 検証

```sh
npm run test:product
```

本番では、変換後プレビュー内のリンク数、全ページの保存直前リンク監査、WordPress下書きのリンク巡回、404、再変換時の重複を追加確認する。
