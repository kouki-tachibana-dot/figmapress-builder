# FigmaPress 実運用品質向上計画

## フォーム値を保護するリンク限定変換（v0.26.74）

- WordPressページURLへの変換対象をElementorの`url`設定とHTML内の`href`に限定する。
- `company`等のページキーと一致するフォーム項目名・ラベル・選択値・一般設定値は変更しない。
- ページリンク、本文リンク、フォーム設定の同時回帰テストで再発を防止する。

## PC/SPロゴのサイトホーム固定（v0.26.73）

- 複数ページサイトではPC/SP双方のロゴリンクを現在ページ内先頭ではなく、作成される論理ホームページへ接続する。
- 単一ページ変換のページ先頭リンクは従来どおり保持し、複数ページ時だけサイトホームへ切り替える。
- ラベル単位リンク検査でロゴのホームURLも検査し、WordPress保存前にPC/SP両方の移動先を保証する。

## 重複リンクを含むラベル単位の移動先保証（v0.26.72）

- ヘッダー、フッター、CTAに同名リンクが複数あっても、各リンクの表示名を正しい論理ページへ固定する。
- 古いFigmaプロトタイプ線が現在ページ先頭へ戻っていても、「役員一覧」「お問い合わせ」など既知のページ名を優先する。
- 全移動先がどこかに存在するだけでは合格にせず、各メニュー・CTAのラベルと移動先が一致しない場合はWordPress送信前に停止する。

## 選択中ページと保存先テンプレートの固定（v0.26.71）

- お問い合わせなどの下層ページを単体プレビューした直後でも、そのテンプレートをホームへ流用せず、対応する論理ページへだけ割り当てる。
- 全ページ事前検証とWordPress保存は同じページ別テンプレート集合を使用し、検証結果と実際の下書き内容の食い違いを防ぐ。
- PC/SPどちらのFigmaフレームIDから開始しても、同じページキーへ解決してホーム・お問い合わせ・フォーム数を安定させる。
- サイト識別子はFigmaファイル単位で固定し、開始ページや共有URL内のnode-idが変わっても既存9ページを更新して重複作成しない。

## プレビュー選択から独立したサイト構成（v0.26.70）

- サイト一式のホームはFigma上の最初の完全なPC/SPページへ固定し、直前にプレビューしたページでは入れ替えない。
- お問い合わせを単体確認してからサイト一式へ切り替えても、ホーム・お問い合わせを含む同じ9ページ構成とリンクキーを保持する。
- 選択中ページによってメニュー移動先や作成ページが変化しないことを回帰テストで保証する。

## 精密表示層を対象にした視覚QA（v0.26.69）

- Figma原本画像を表示する精密表示層と、透明な編集・操作層が重なる場合は、実際に見える精密表示層を画素比較対象として優先する。
- 透明操作層はメニュー、リンク、フォーム、入力枠座標の機能検査で引き続き検証し、視覚スコアへ透明層の余分な高さを混入させない。
- 精密表示層がない通常変換や実WordPressスナップショットでは、従来どおり最大の可視レイアウトを比較対象にする。

## スマホ横長・枠線フォームの座標保持（v0.26.68）

- スマホで横幅がフォームの75%を超える入力欄も、ページ幅内の安全な範囲なら実入力枠として認識する。
- 塗りなし・枠線のみのRectangleも入力枠として扱い、ラベルとの上下関係から各項目へ対応付ける。
- PC/SP双方のフォーム数だけでなく、全フォームの入力欄座標診断が合格することを下書き前の必須条件にする。

## スマホ分割フォームの帯域合成（v0.26.67）

- 入力項目が1つのグループではなく複数の一般名グループへ分割されていても、先頭項目から送信ボタンまでを1つのフォームとして合成する。
- フォーム帯域外のヘッダー、案内、資料ダウンロード、フッターは合成対象から除外し、ページ構成を保持する。
- 画面の表示リリース番号を実際の本番コードと一致させ、キャッシュ更新の確認を明確にする。

## 名称のないスマホフォームグループ検出（v0.26.66）

- `Group 400`のような一般名のグループでも、実際のメール、担当者、質問、送信欄が揃っていればフォームとして検出する。
- 候補が複数ある場合はFigma上の入力項目を最も多く保持するグループを優先し、スマホ側の入れ子構造でも全項目を失わない。
- PC直下型とスマホ入れ子型を同一テスト内で変換し、PC/SP双方の実動フォームが生成されることを必須にする。

## 建工101型・散在フォームの全項目機能化（v0.26.65 / Connector v0.17.30）

- お問い合わせ項目、企業名、読み方、担当者、ふりがな、住所、電話、メール、流入元、質問、個人情報同意がページ直下に散在していても、PC/SPごとに1つのフォームへ合成する。
- ラジオ、テキスト、メール、電話、複数行、同意チェックをElementorで編集できる繰り返し項目として保持する。
- 必須条件、メール形式、文字数、選択肢、同意をWordPress送信時にも再検証し、設定外の項目は受け付けない。
- Connector v0.17.30未満では動的フォームを含むサイト作成を開始せず、更新案内を表示する。

## ページ直下の散在ヘッダー合成（v0.26.64）

- メニュー文字、ロゴ、ハンバーガーが同じFigmaグループに入っていないページでも、上端帯域から1つの実動ヘッダーを合成する。
- 合成済みの元レイヤーはネイティブ出力から除外し、Elementor編集画面で文字やロゴを二重表示しない。
- PCのメニュー文言をスマホのロゴ・ハンバーガー構造へ引き継ぎ、PC/SP双方を同じ全ページリンクへ接続する。
- 本文のヒーローとページ下部のフッターは合成対象に含めず、そのまま保持する。

## 一般レイヤー名ヘッダー・実動機能ゲート（v0.26.63）

- `Group 85`のような一般名でも、ページ上端の位置、横幅、高さ、実際のページ文言からヘッダーを特定する。
- PCのメニュー文言を、メニュー項目を非表示にしたスマホヘッダーへ安全に引き継ぎ、ハンバーガーメニューを実動Widgetへ変換する。
- ページ下部の同じ文言をフッターとして維持し、ヘッダーへ誤変換しない。
- WordPress送信前に全ページのPC/SP実動メニュー、全ページへのメニュー移動先、お問い合わせフォームを検査する。
- 機能不足が1件でもあれば全ページ下書き作成を開始せず、ページ名と不足内容を表示する。

## 1クリック完走の待機・再取得（v0.26.62）

- Figma精密画像の一時失敗時は12秒、24秒、36秒と待機を延ばし、最大4回まで同じページを自動再取得する。
- 待機中は合格済みページ数と再取得中のページ名を表示し、停止と誤認させない。
- 手動再開用のページキャッシュも維持し、長時間のFigma制限でも合格済みページを失わない。

## 実Figma全ページ取得の自動復旧（v0.26.61）

- 精密画像取得が一時的に失敗したページだけを最大3回、自動的に間隔を空けて再取得する。
- Figmaページは1ページずつ取得し、PC/SP画像要求の集中とページ間の相互失敗を防ぐ。
- 合格済みページをブラウザ内に一時保持し、再実行時は失敗ページから再開する。
- APIが2ページを受け取った場合も直列処理し、Figma画像APIへの同時負荷を抑える。

## 全ページ事前検証・リンク到達性ゲート（v0.26.60）

- WordPressへ送信する前に、Figmaで検出した全ページのElementorデータを本番と同じAPIで生成する。
- 各ページのPC/SP精密表示、未解決リンク、不正URL、存在しないアンカーを一括検査する。
- 計画された全ページがリンク先として到達可能であることを確認する。
- 事前検証が未実施または不合格の場合は、サイト一式の下書き作成を開始しない。

## ページリンク完全性・製品ゲート（v0.26.59）

### 実装

1. Figma全体で検出したPC/SPページIDを、選択ページの剪定前に論理ページキーへ対応付ける。
2. 別ページのプロトタイプ遷移、文言から補完したメニュー・CTA、画像リンクを同じ論理URL形式でElementorとプレビューへ出力する。
3. WordPressが返した実ページURLで全テンプレートを再帰的に書き換える。任意のページ名にも対応し、再実行しても結果を変えない。
4. 保存直前にリンク監査を行い、未解決ページ、存在しないアンカー、危険なURLがあれば対象ページを保存しない。
5. Figma精密画像の上に透明な操作レイヤーを重ね、見た目を変えずにプレビュー上でリンクを押せるようにする。
6. 表示中のページ名と古いFigmaプロトタイプ配線が矛盾する場合は表示ページ名を優先し、日付を電話番号として扱わない。
7. 精密表示上のリンク領域は背景、枠、余白、影、文字色を完全に無色化し、画素比較に影響させない。
8. 操作レイヤーのPC/SPルート背景と子テキストの色指定も透明化し、原本画像を覆わない。
9. サイト一式の全サブページにもPC/SP精密表示を取得し、不足時はWordPress保存を開始しない。

### 完了条件

- PC/SPのページフレームが同じWordPressページへ到達する。
- メニュー、CTA、画像、メール、電話、外部URL、ページ内アンカーが保持される。
- 全ページ保存用テンプレートに内部プレースホルダーが残らない。
- リンク書換えは冪等で、再変換・更新時にURLや下書きが重複しない。
- `docs/ACCEPTANCE_CRITERIA.md` の保存禁止条件をすべて回避し、製品試験と本番確認に合格する。

## 建工101 文字表示完全性・99.9%反復検証（v0.26.54）

3. 回帰テスト、型検査、lint、本番ビルドを通す。
4. 本番で再変換し、PC/SPの文字表示完全性と視覚差分を再測定する。

- PC/SPのページ高差が0%で、重大な欠落・重なり・横はみ出しがない。
- 99.9%未達時は達成と表示せず、残差カテゴリと次の改善対象を記録して反復を続ける。
