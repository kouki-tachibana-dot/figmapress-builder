# FigmaPress 実運用品質向上計画

## 基準と対象

- デザイン基準: Figma「竹内きよ子様 リネーム用」`node-id=46-12`
- 対象サイト: `takeuchikiyoko.com` の既存Elementor下書き6ページ
- 変更境界: 下書きと未割り当てメニューだけを更新し、公開・メニュー割り当て・既存公開ページの変更は行わない
- 基準画面幅: PC 1440px、スマートフォン 390px。Figma内のスマートフォン用フレームを幅・並び・表示切替の正とする

## コンポーネント対応

| Figma上の役割 | Elementorでの出力 | 確認事項 |
| --- | --- | --- |
| ヘッダー・ナビゲーション | `figmapress-nav` | PC/SP切替、メニュー開閉、ロゴ、CTA、ページ/アンカーリンク |
| 画像・背景画像 | Image widget / Container background | WordPressメディアへ永続化、縦横比、切り抜き位置 |
| スライダー | `figmapress-carousel` | 前後操作、スワイプ、表示枚数、端の余白 |
| 問い合わせ | `figmapress-contact-form` | 表示、入力、検証、送信経路。実送信は明示許可があるまで行わない |
| アコーディオン | `figmapress-accordion` | 開閉、キーボード操作、初期状態、高さ崩れ |
| ページ間導線 | `figmapress-link` / WordPress menu | 6ページのslugとアンカーを解決し、リンク切れを残さない |

## 実装順序

1. 大容量の分割保存後も、画像保存が完了したと誤判定せず、再開可能なメディア保存へ必ず引き渡す。
2. 既存の同一source keyを使い、ページIDと未割り当てメニューIDを維持したまま6ページを再構築する。
3. Figma配信URLがElementor本文と描画HTMLに残っていないことを確認する。
4. PC/SPの視覚差分、横はみ出し、ヘッダー、フッター、カルーセル、フォーム、アコーディオン、リンクを実ページで確認する。
5. 同じ変換を再実行し、ページ・メニュー・項目が重複しないことを確認する。
6. 複数ページの画像保存が時間上限で止まった場合も、対象ページ固有の保存IDで再開し、完了後は残りのページ構築を自動継続する。
7. 全6ページのスマートフォン展開メニューを後続の画像・本文・フォームより前面に保ち、各ページリンクを押せるようにする。
8. FigmaPress所有のElementor下書きを通常編集した場合は、ブロックエディタ起動前にElementor編集画面へ案内して共有サーバーのメモリ超過を避ける。

## 完了条件

- すべての対象画像がWordPressメディアURLになり、期限付きFigma画像URLが残らない。
- 既存6ページと同じIDを更新し、新しい重複下書きを作らない。
- メニューは6項目のまま未割り当てを維持し、各リンクが対象ページまたはアンカーへ到達する。
- 1440px/390pxで重大な崩れ、横スクロール、縦書き化、非表示フォームがない。
- ヘッダー、カルーセル、フォーム、アコーディオンが見た目だけでなく操作できる。
- 全6ページの390px表示でメニューを展開でき、後続コンテンツに遮られず各リンクへ移動できる。
- FigmaPress所有ページの「編集」がElementorへ到達し、PHPメモリ上限エラーを表示しない。一般ページの編集経路は変更しない。

## 未確定事項

- 公開とメニュー位置への割り当ては今回の対象外とし、完成下書きの承認後に行う。
