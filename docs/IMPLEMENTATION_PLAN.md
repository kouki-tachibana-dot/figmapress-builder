## PC／タブレット／スマホ3段階レスポンシブ（v0.30.0）

### 正本・対象・変更境界

- PCは1025px以上、タブレットは768〜1024px、スマホは767px以下として、Elementorの標準ブレークポイントと同じ境界で扱う。
- Figmaに同一ページのTablet／タブレット／iPadフレームがある場合は、そのフレームの幅・高さ・比率・文字・画像・機能を正本にする。
- タブレットフレームがないページはPCルートを継承するが、タブレット99.9%とは表示しない。1024pxと834pxで横はみ出し、縦書き、重なり、文字欠落、操作不能がないことだけを独立検査する。
- 既存のWordPress下書き、未割り当てメニュー、公開状態を維持し、品質検査に通る前は下書きを更新しない。

### 実装順序

1. ページ候補検出をPC／タブレット／スマホの3フレームに拡張し、見出し内容と配置から同一ページへ関連付ける。
2. 選択・剪定・ページ間リンク・画像取得で3フレームのIDを一緒に保持し、タブレットだけの画像やプロトタイプ遷移を落とさない。
3. Elementorへdesktop／tablet／mobileの独立ルートを出力し、Tabletルートは`hide_desktop`と`hide_mobile`、PCルートはTabletがある場合だけ`hide_tablet`を持たせる。
4. 各ルートへFigma原寸幅・高さ・アスペクト比を記録し、768／1024のブレークポイント定義をテンプレートにも保存する。
5. 保存前のネイティブ構造検査をTabletのmain、header、footer、H1、リンク、Form、Accordion、Nav Menuまで拡張する。
6. Tablet基準フレームがあるサイトは全ページの端末別画素比較へ追加し、9ページなら最大27画面を同じ99.9%ゲートで検査する。
7. 834px縦向きと1024px横向きで、横スクロール、文字の縦書き、画像切れ、重なり、44px操作領域、メニュー・フォーム・アコーディオンを実WordPress下書きでも確認する。

### 完了条件

- タブレットフレームがあるページは768〜1024pxでPC・スマホルートと同時表示されず、Tabletルートだけが表示される。
- タブレット原寸の幅・高さ比率を保持し、同一幅のFigma比較で99.9%以上かつ既存の差分上限を満たす。
- タブレットフレームがないページはPC継承であることを明示し、Tablet 99.9%を誤表示しない。
- PC／タブレット／スマホの全リンクと機能Widgetが同じ論理ページ・機能へ到達し、Elementorで個別編集できる。
- 全自動試験、型検査、lint、本番ビルド、実WordPressの834px／1024px確認に合格する。

## 知覚構造99.9%と独立欠落ゲート（v0.27.8）

- PC/SPの知覚点は、JPEG基準画像では中心5×5の局所構造誤差、PNG基準画像では原画素誤差を用い、8bit色域に対する正規化二乗誤差から算出する。
- 99.9点だけでは合格にせず、実質差分面積2%未満、内容領域差分3%未満、最大区間差分5%未満、ページ高差0.1%未満を同時に必須とする。
- 完全RGBA一致だけを100点とし、生差分がある知覚一致は最大99.9点に制限する。生差分、エッジ等価、JPEG局所等価、実質差分をすべて併記する。

## 長尺JPEGの局所知覚比較（v0.27.7）

- 長尺FigmaフレームはFigma APIの制約でJPEG基準画像になるため、個別画像・ブラウザ描画との高周波な再圧縮差を生RGBA差分とは別に記録する。
- 両画像に実エッジがあり、エッジ強度差16/255以内、中心5×5の平均色差8/255以内の場合だけJPEG局所等価とする。
- 平坦な欠落、色変更、コントラスト変更、3px以上の位置ずれは局所等価に含めず、実質差分として不合格にする。

## 長尺Figma基準画像の優先取得（v0.27.5）

- PC/SP基準画像を、生成プレビュー内の多数の画像より先に高優先度で取得する。
- 長尺ページで同一オリジンの画像キュー後方に基準画像が滞留し、正常な画像を45秒タイムアウトと誤判定する問題を防ぐ。
- 基準画像の取得完了後にプレビュー資産・フォント・スタイルを待機し、99.9%ゲートを省略せず最後まで実測する。

## 同一画素グリッド・知覚差分99.9%ゲート（v0.27.4）

### 視覚の正本と測定条件

- Figma APIが返したPC/SP基準画像を視覚の正本とし、生成結果も基準画像と同じ実画素幅で描画する。長尺PCを一律800pxへ再縮小して二重補間しない。

- 完全な画素一致だけを100点とし、生差分が残る知覚一致は最大99.9点に制限する。

### 補正と回帰防止

1. PC/SPをFigma基準画像の実画素幅で再測定し、二重縮小による文字輪郭・画像境界の偽差分を除去する。
2. 文字、画像、背景・枠の補正は対象領域だけでなくページ全体の点数と実質差分率も非悪化であることを必須にする。
3. 対象領域だけ改善して全体点が下がる補正は自動的に巻き戻す。
4. 差分レポートには実質差分と生差分、エッジ等価率、測定幅を併記し、99.9%の根拠を追跡可能にする。
5. 同一画像、1〜2pxアンチエイリアス・縮小輪郭差、欠落領域、3px以上の位置ずれ、補正の全体非悪化を回帰テストする。

### 完了条件

## Elementorネイティブ再構築（v0.27.0）

### 目的

- 公開画面とElementor編集画面を、同じElementorコンテナ・ウィジェット構造から描画する。
- Figma全画面スナップショットを公開コンテンツとして保存せず、視覚QAの比較資料としてだけ使用する。
- 見出し、本文、リンク、画像、ナビゲーション、フォーム、アコーディオン、カルーセルをElementor上で個別に選択・編集できる状態を必須とする。

### 公式Elementor構造との対応

| Elementorの仕組み | FigmaPressの出力 | 必須検査 |
| --- | --- | --- |
| Page JSON `version: 0.4` | `ElementorTemplate` | `content`がコンテナ／ウィジェットの有効な木であること |
| Container | Figma Frame / Group | 子要素、幅、高さ、背景、余白、配置をElementor設定として保持 |
| Widget | text-editor / image / FigmaPress機能Widget | `widgetType`と登録済みコントロールが一致すること |
| Responsive values | desktop値と`_tablet`／`_mobile`、または端末別ルート | PC/SPの表示切替、横はみ出し、操作対象を確認 |
| Page settings | 背景、タイトル非表示、Webフォント、ネイティブ構造識別 | 全画面画像や透明文字による代替を禁止 |

### 実装順序

1. `convert`と複数ページ変換から精密表示スタックの挿入を外し、Figma参照画像はAPIレスポンスの比較資料にだけ残す。
2. ネイティブElementorテンプレートへ構造バージョンとPC/SP参照IDを記録する。公開HTMLには参照画像を出力しない。
3. 保存前検査で、要素IDの一意性、コンテナ／ウィジェットの木、登録Widget、実テキスト、画像、PC/SPルート、機能Widgetを検証する。
4. 全画面画像、`figmapress-exact-*`、透明化した文字・Widgetを含むテンプレートはWordPress保存前に拒否する。
5. 文字表示検査へ文字色と`-webkit-text-fill-color`を追加し、透明文字を「実描画」と誤判定しない。
6. WordPress保存後はElementorの実フロントエンド描画を取得し、実テキスト、リンク、フォーム、PC/SP、アクセシビリティを再検査する。

### 完了条件

- 公開画面にFigma全画面画像がなく、見えている全文章がHTMLテキストである。
- Elementorナビゲータでセクション、文字、画像、機能Widgetを個別に選択・編集できる。
- 公開画面とElementor編集画面で同じネイティブ構造が描画され、透明な操作レイヤーを使わない。
- PC 1440px、タブレット1024px、スマホ390pxでFigmaと比較し、意図しない縦書き、欠落、重なり、横スクロールがない。
- 変換、型検査、lint、ビルド、WordPress保存、実ページブラウザ試験に合格する。

## 全9ページ・18画面の99.9%出荷ゲート（v0.29.0）

### 基準と変更境界

- Figma「株式会社建工101」の各ページPC/SPフレームを唯一の視覚基準とし、全9ページ18画面を同じ画素条件で比較する。
- PC/SPは各Figmaフレームの原寸比率で測定し、追加の1024px・768pxはElementorのレスポンシブ構造と横はみ出し確認に使う。
- 既存下書き#184626〜#184634、未割り当てメニュー137、公開状態を維持する。品質ゲート未合格時はWordPressへの更新を始めない。

### 実装順序

1. 全ページ取得APIから、Elementorテンプレートに加えてページ固有のPC/SP基準画像と高忠実度プレビューを返す。
2. 全ページ構造検査の後、PC/SPを直列で18回画素比較し、99.9%判定と最低一致度を記録する。
3. 各レスポンシブルートに`main`、実動メニュー相当の`header`、`footer`、ちょうど1個のH1があることを検査する。
4. `SampleSample…`、Lorem ipsum、ダミー文言、繰り返し仮テキストを検出し、原稿を自動捏造せず送信を停止する。
5. ページ間リンク、Elementor URL Control、クリック可能Containerの入れ子、Form・Accordion・Nav Menuの実ウィジェットを従来どおり再検査する。
6. 単体試験、型検査、lint、本番ビルドを通し、本番の全ページ事前検証で同じゲートを再実行する。

### 完了条件

- 各PC/SPルートにmain/header/footer/H1が揃い、見出し順、キーボード操作、リンク先、フォーム項目がElementor上で編集可能である。
- 仮テキスト、未設定リンク、未解決ページ、危険URL、入れ子リンクが0件である。
- 不合格時は対象ページ・端末・一致度・不足構造を表示し、下書きを変更しない。画質差分の手動承認による迂回は設けない。
