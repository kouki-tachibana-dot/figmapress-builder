# FigmaPress 実運用品質向上計画

## 建工101 文字表示完全性・99.9%反復検証（v0.26.49）

### 基準と測定

- 視覚基準はFigma「株式会社建工101」ホームのPC 1440×8058、スマホ440×5390とする。
- 旧`release`指定を最新版へ自動更新し、古い変換画面を最新版と誤認させない。
- ページプレビュー内の全Figmaテキストについて、文字Rangeが実際の描画幅・高さを持つことを検査する。DOMに存在するだけでは合格にしない。
- 画素スコアは閾値を緩めず、PC/SP別の原本、生成画像、ヒートマップを毎回目視する。

### 反復順序

1. 旧URLと最新版URLの双方から同一ホームを変換し、文字表示数が全件一致することを確認する。
2. 文字、画像、背景の順に安全な補正だけを適用し、改善しない補正はロールバックする。
3. 回帰テスト、型検査、lint、本番ビルドを通す。
4. 本番で再変換し、PC/SPの文字表示完全性と視覚差分を再測定する。

### 完了条件

- プレビュー上の文字表示が全件合格し、0px文字、縦書き化、意図しない折返しがない。
- PC/SPのページ高差が0%で、重大な欠落・重なり・横はみ出しがない。
- 99.9%未達時は達成と表示せず、残差カテゴリと次の改善対象を記録して反復を続ける。

## 建工101 複数フレーム選択・高忠実度変換（v0.26.32）

### 基準と権限境界

- 視覚基準: Figma「株式会社建工101」`PaNNOGcUo5Uyg5UrEsYeyd`。Figmaの各PC/SPページフレームを正とし、`node-id=0:1` のページ全体は単一サイトとして扱わない。
- 現行差分: ページルート直下の91レイヤーを1サイトに結合し、ホームPCと会社案内SPなど別ページを誤って組み合わせていた。生成プレビューでは先頭画面が空白になり、重複テキストも出力された。
- 変更境界: FigmaPressの読込・候補選択・変換ロジックを改修する。WordPressは下書き検証までとし、公開ページ、ドメイン、メニュー割り当て、フォーム実送信は変更しない。
- 比較幅: 選択したFigmaフレーム本来のPC幅とスマホ幅を使用し、追加確認は1440px、1024px、390pxで行う。

### 実装順序

1. FigmaのCANVAS直下からWebページ候補だけを抽出し、レイヤー名、主要見出し、座標、画面寸法を記録する。
2. PC/SPをファイル全体の最大サイズではなく、主要見出しと近接配置でページ単位に対応付ける。内容が異なる画面は自動結合しない。
3. 複数ページ候補がある場合は変換を止め、ページ選択UIを表示する。選択後は該当PC/SPフレームだけにFigmaデータを剪定して変換する。
4. 選択フレームIDをWordPress下書きのsource keyと複数ページ再取得に引き継ぎ、別ページへの差し替わりと重複下書きを防ぐ。
5. 建工101型の複数PC/SPフィクスチャで候補抽出、誤ペア防止、選択剪定を回帰テストする。
6. 実Figmaで候補一覧、ホームページ変換、PC/SPプレビュー、画像、文字、ヘッダー、フッター、横はみ出しを確認する。

### 完了条件

- `node-id=0:1` を入力しても91レイヤーを1ページに混在させず、変換するページ候補を選べる。
- 「ホームPC＋ホームSP」「会社案内PC＋会社案内SP」のように同内容の端末フレームだけを統合し、異なる見出しのフレームを組み合わせない。
- 選択後のプレビュー先頭に空白がなく、別ページの本文や重複テキストが混入しない。
- PC/SPのFigma基準画像が選択フレームと一致し、Visual QAが誤った別ページを比較しない。
- テスト、型検査、lint、production build、ブラウザ操作確認に合格する。

### 未確定事項

- Figma接続アプリは再認証が必要なため、実FigmaのMCP比較は接続復旧後に行う。ブラウザ上の既存PAT変換は候補選択の実運用確認に利用する。
- 建工101の全ページ公開は今回の自動改修範囲外。最初にホーム下書きを承認し、その後に各ページを同じ選択方式で作成する。

## 実装順序

1. 大容量の分割保存後も、画像保存が完了したと誤判定せず、再開可能なメディア保存へ必ず引き渡す。
2. 既存の同一source keyを使い、ページIDと未割り当てメニューIDを維持したまま6ページを再構築する。
3. Figma配信URLがElementor本文と描画HTMLに残っていないことを確認する。
4. PC/SPの視覚差分、横はみ出し、ヘッダー、フッター、カルーセル、フォーム、アコーディオン、リンクを実ページで確認する。
5. 同じ変換を再実行し、ページ・メニュー・項目が重複しないことを確認する。
6. 複数ページの画像保存が時間上限で止まった場合も、対象ページ固有の保存IDで再開し、完了後は残りのページ構築を自動継続する。
7. 全6ページのスマートフォン展開メニューを後続の画像・本文・フォームより前面に保ち、各ページリンクを押せるようにする。
8. FigmaPress所有のElementor下書きを通常編集した場合は、ブロックエディタ起動前にElementor編集画面へ案内して共有サーバーのメモリ超過を避ける。
